## Исправленные баги (код)

1. **`app/Modules/Payments/Services/RefundService.php`** — `PaymentRepository` использовался
   без `use`. Резолвился в несуществующий `Nabilet\Modules\Payments\Services\PaymentRepository`
   → 500 на `/api/v1/payments` и падение `artisan route:list`. Добавлен импорт из `Repositories`.
2. **Миграция `2026_09_20_000200_002_content.php`** — `unique(['source'])` на `VARCHAR(2048)`
   даёт 8192 байта > лимита InnoDB 3072 (ошибка 1071). Канон (`migrations.sql`) использует
   префиксный индекс `source(512)`. Заменено на сырой `DB::statement('ALTER TABLE redirects ADD UNIQUE KEY uq_redirect_source (source(512))')`.
3. **Миграция `2026_09_20_000700_007_analytics.php`** — `CREATE INDEX IF NOT EXISTS` не
   поддерживается MySQL (ошибка 1064). Убран `IF NOT EXISTS` (блок выполняется только при
   создании таблицы, индекс не может существовать).
4. **Миграция `2026_09_20_001200_fix_offline_bundles_unique_constraint.php`** —
   `DB::selectOne('select version()')->version` не определена в MySQL (колонка называется
   `version()`), плюс ветка MySQL использовала невалидный `DROP CONSTRAINT`. Переписано на
   проверку `information_schema.statistics` через `DB::selectOne` + `DROP INDEX`.
5. **Маршруты `auth:sanctum` → `auth:api`**: `app/Modules/Auth/routes/api.php` и
   `app/Modules/Venues/Halls/routes/api.php`. `config/auth.php` объявляет только guard'ы
   `web` и `api` (`session_token`), guard `sanctum` не определён; тест `AuthWiringTest` требует
   `auth:api`. Итог `php tests/run.php`: **639 passed, 0 failed** (было 637/2).
6. **`tools/verify-migrations.php`** — инструмент не видел индексы, созданные сырым DDL
   (из-за этого падал `heatmap_events.idx_heatmap_page_time`, а после моей правки и
   `redirects`). Добавлен разбор `CREATE [UNIQUE] INDEX` и `ALTER TABLE ... ADD [UNIQUE] KEY`
   из `rawStatements`. Падение heatmap устранено, регрессий нет.
