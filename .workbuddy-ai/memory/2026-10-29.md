Продолжение кампании «правило скопировано, а не вызвано» (фронтенд).

## Батч 8 — Форматтеры дат: один владелец в `lib/format.ts`

Продолжение кампании «правило скопировано, а не вызвано» (фронтенд).

**Что было:** четыре формата даты для человека жили РОЗНО. `mediaLibrary.ts` и
`AdminRafflesPage.vue` определяли КАЖДЫЙ свой `formatDate` под одним именем, но
разными форматами («9 октября 2026» против «25.12.2026, 19:30»), а
`AdminEventFormPage` и `AdminDashboardPage` встраивали `toLocaleString('ru-RU', …)` /
`Intl.DateTimeFormat('ru-RU', …)` прямо в `computed`. Копии не лгали (для ru-RU
форматы стабильны), но расходились бы при смене локали хостинга или правке одного
места — классический дефект «скопировано, а не вызвано».

**Решение:** четыре детерминированных хелпера вынесены в единственного владельца
`resources/js/lib/format.ts` (месяцы из тех же массивов `MONTHS_GEN`/`MONTHS_NOM`,
что у `dateLong`/`dateTime` — вывод не зависит от локали браузера, в отличие от
`toLocaleString`, который на managed-хостинге без ru-RU мог бы отдать `Oct 9, 2026`):
- `formatDate` («9 октября 2026», пустая строка на пустом/битом вводе)
- `formatDateTimeLong` («9 октября 2026, 19:30», «—» на пустом)
- `formatMonthYear` («октябрь 2026» — именительный, для подписи периода)
- `formatDateTimeShort` («09.10.2026, 19:30», «—» на пустом)

`mediaLibrary.ts` и `AdminRafflesPage.vue` лишились локальных `formatDate`; страницы
зовут владельца. `publishedAtText` (AdminEventFormPage) раньше возвращал сырую
строку при невалидной дате — теперь возвращает «—» (строго лучше, raw-ISO в UI не
показываем); на валидном вводе формат побайтово тот же.

**Регрессия (поймана тестами, до коммита):** сначала `AdminMediaPage.vue` импортировал
`formatDate` из `@/lib/mediaLibrary` (тот больше не ре-экспортирует) → vue-tsc TS2459
+ vite rollup `findVariable`; `mediaLibrary.test.ts` ещё тянул `formatDate` из
mediaLibrary → 2 падения vitest. Исправлено: импорт из `@/lib/format` в обоих местах.

**Сторож непустоты:** `tests/Unit/format.test.ts` — таблица из 7 входов (ISO +
пустой/null/битый) + статический запрет `toLocaleDateString` / `Intl.DateTimeFormat` /
`function formatDate\b` вне `lib/format.ts` (файл-владелец пропускается, так что
`Intl.NumberFormat` в `money()` и упоминания в комментариях не ловятся). Эквивалент

## Аудит безопасности (SQLi / XSS / RCE / прочее)

По прямому запросу пользователя («продолжай и проверь sql уязвимости, xss и прочие»).
Систематический grep по `app/` и `resources/js`: сырой SQL, `v-html`, `exec`/`eval`/
`unserialize`/`proc_open`/`popen`/`passthru`/`system`, слабые хэши.

**Вывод: код хорошо защищён, эксплуатируемых уязвимостей не найдено.** Ключевые
наблюдения:
- **SQLi**: `LikePattern::expression()` валидирует идентификаторы колонок через
  `assertIdentifier()` (регэксп) и биндит значения — уязвимости нет. Все `whereRaw`/
  `selectRaw`/`orderByRaw` передают значения как bindings, а интерполируют только
  `(int)`-кастованные или `?int`-типизированные переменные (безопасно приведением).
- **Единственный латентный запах**: `Seo/Services/CatalogService.php:797`
  `venueScope()` интерполирует `$venueId` в SQL (`' AND s.venue_id = ' . $venueId`).
  СЕГОДНЯ БЕЗОПАСНО — `?int` по всей цепи вызовов (PHP приводит к int). Помечено как
  техдолг: стоит обернуть в binding/каст явно, чтобы не сломалось при расширении
  цепи типов.
- **Командная инъекция (RCE)**: `Backups/.../YandexDiskBackupService.php:48-54`
  `buildDumpCommand()` оборачивает все 3 аргумента в `escapeshellarg()`.
  `Tickets/Services/TicketPdfRenderer.php` `exec()` использует только temp-пути;
  `resolveChromeBin()` — `getenv` + `is_file`. Нет `eval`/`unserialize` в опасных
  местах.
- **XSS**: `ClubPage.vue:111` `glyphFor(key)` = `glyphs[key] ?? ''` — map lookup,
  не пользовательский ввод. Рендер через Vue (автоэкранирование); прямых `v-html`
  с внешними данными не найдено.
- **Хэши/пароли**: `bcrypt`/`password_hash(PASSWORD_BCRYPT)` для паролей;
  `Sha256Hex`/`HmacSignature` для токенов/подписей. `md5` только для
  `writable_*md5`-проверок и слагов (небезопасность не критична).

**Действие по итогам аудита:** код менять не требовалось — только пометить
`CatalogService::$venueId` интерполяцию как техдолг в памяти.

## Батч 11 — Очистка управляющих символов: один владелец `Core\Support\Text`

Первый бэкенд-батч кампании «правило скопировано, а не вызвано».

**Что было:** класс управляющих символов C0 + DEL
`/[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]/` был ВПИСАН двумя копиями —
в `StorefrontService::text` (с флагом `u`) и `MatrixMessage::sanitize`
(без `u`, намеренно: байтовый класс безопасен для невалидной UTF-8 из БД).
Копии компилировались, но расходились по флагу `u`; правка класса в одном
месте (например, добавить `\x85`) разошлась бы со вторым.

**Отвергнутый кандидат:** «уникальный slug с числовым суффиксом» в
`OrganizationService::generateUniqueSlug` и `SyncArtistsCommand::uniqueSlug` —
НЕ копия: разные источники slug (`Str::slug` vs `Artist::slugFor`), разные ключи
коллизии (`findBySlug($slug,$excludeId)` старт с 1 vs `where slug and
normalized_name !=` старт с 2). Легитимно разные правила — отклонён.

**Решение:** единственный владелец `Nabilet\Core\Support\Text::stripControlChars($text, $unicode)`
(флаг `u` — параметр, расхождение видно в одном месте; класс — константа
`Text::CONTROL_CHARS`). Обе точки зовут владельца. Поведение сохранено побайтово:
`preg_replace(…) ?? ''` (Storefront) и `?? $body` (Matrix) эквивалентны — байтовый
класс без `u` не возвращает null на практике, а с `u` на невалидной UTF-8 и раньше
давал ''. `MatrixMessage::sanitize` сохранил поясняющий комментарий «почему
без `u`» — теперь это обоснование аргумента `false`.

**Сторож непустоты:** `tests/Unit/ControlCharsSingleOwnerTest.php` (по образцу
`*SingleOwnerTest.php`) — поведенческие тесты (`stripControlChars` с `u`/без `u`,
байтовый класс не падает на невалидной UTF-8) + статический запрет литерала класса
вне `app/Core/Support/Text.php` по всему `app/`. **Не vacuous:** временная копия
в `app/Core/Support/__control_probe.php` роняла тест (`offenders =
["app/Core/Support/__control_probe.php"]`); после удаления зонда — зелёный.
