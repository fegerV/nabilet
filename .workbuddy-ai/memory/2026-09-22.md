# 2026-09-22 — Дизайн-система NABILET Core

## Что сделано

Запустил фронтенд-каркас NABILET (Vue 3 + TS + Vite + Pinia + Tailwind + Konva) и собрал дизайн-систему под три клиентских поверхности (витрина, админка организатора, редактор залов).

**Артефакты:**
- `package.json`, `vite.config.ts`, `tsconfig.json`, `tailwind.config.ts`, `postcss.config.js`, `index.html` — каркас.
- `resources/css/app.css` — дизайн-токены (палитра, темы, радиусы, тени, motion).
- `resources/js/lib/` — утилиты (cn, format, hall, types, mock).
- `resources/js/stores/ui.ts` + `cart.ts` — Pinia-сторы.
- `resources/js/components/ui/` — 14 компонентов (NButton, NInput, NSelect, NCheckbox, NBadge, NStatusBadge, NCountdown, NBottomSheet, NModal, NSegmented, NStepper, NEmptyState, NDataTable, NToastHost).
- `resources/js/components/seat/` — SeatMap (SVG, 7 состояний места), SeatLegend, OrderSummary.
- `resources/js/components/storefront/` — EventCard, TicketCard.
- `resources/js/layouts/` — StorefrontShell, AdminShell.
- `resources/js/pages/`:
  - `storefront/`: CatalogPage, EventPage, SeatSelectionPage, CheckoutPage, PaymentResultPage, TicketsPage.
  - `admin/`: AdminDashboardPage, AdminOrdersPage, AdminEventsPage, AdminPlaceholderPage.
  - `hall-editor/`: HallEditorPage (Konva-готовая обвязка).
- `resources/js/router/index.ts` — hash-роутинг, /embed и /admin ветки.
- `resources/js/main.ts`, `App.vue` — точка входа.
- `tools/inline-preview.mjs` — сборка автономного `dist-preview/ui-preview.html` (482 КБ, всё в одном файле, открывается двойным кликом).
- `docs/UI-DESIGN.md` — полная спецификация дизайн-системы с маппингом на ТЗ.

**Ключевые баги, которые поймал:**
1. `<slot />` вместо `<router-view />` в layout-компонентах маршрутов — дочерние роуты рендерились в никуда, экран был пустой. Зафиксил в StorefrontShell + AdminShell.
2. Touch targets в хедере были 36px (h-9 w-9), а ТЗ §76 требует ≥44px — поднял до h-11 w-11.
3. ToastHost был `fixed top-0` и перекрывал sticky-хедер — сместил на `top-20`.
4. TicketCard: грид-айтем без `min-w-0` раздувал карточку за пределы px-4, бейдж клипался. Добавил `min-w-0` на article + row.

**Сборка:** `npm run build:preview` → 482 КБ автономный HTML. Скриншоты в `.shots/` (12 экранов, desktop + mobile).

**Известные расхождения** (в roadmap документа): 9 из 11 инструментов Hall Editor, виртуализация для 5000+ мест, реальное подключение Telegram WebApp SDK, i18n.

## Решения

- **Тёмная тема по умолчанию** — медиа-контент выигрывает; светлая — альтернатива.
- **Hash-роутинг** — SPA внутри Laravel и внутри чужого iframe (без серверного rewrite).
- **Один фронтенд для Web + Telegram Mini App + Embed** — отличается только инициализацией темы и поведением `useTelegramTheme()`.
- **Бренд violet + акцент coral** — единственный «эмоциональный» цвет (accent), остальное — нейтральное, чтобы фокус держался на обложках событий.

## Амфитеатр (полукруглые ряды) — позже в ту же сессию

По запросу «можно ли делать ряды полукругом, как в амфитеатре» добавил вторую форму раскладки в `pages/hall-editor/HallEditorPage.vue`:

- Новый тип `SectorShape = 'grid' | 'arc'` + поля в `ESector`: `shape`, `arcSpread`, `arcBaseR`, `arcRowGap`, `arcOffsetX`, `arcOffsetY`.
- Форма `form` получила `shape: 'grid' | 'arc'` и `arcSpread: number` (по умолчанию 160°).
- Хелпер `arcSeatXY(sector, r, n, seatsPerRow)` — координата места на концентрической дуге. Базовая формула: радиус ряда `R = R0 + r * (SEAT+ROW_GAP)`, угол `α = -θ/2 + n*θ/(seatsPerRow-1)`, точка = `(R·sinα + offsetX, R·cosα + offsetY)`. Центр кривизны расположен так, что передний ряд близко к сцене, края загибаются назад (амфитеатр смотрит на сцену выпуклостью).
- `generateSector()` ветвится по `shape`: для arc — считает `R0 = (seatsPerRow-1)*(SEAT+GAP)/θ` (равный шаг по дуге), центрирует по X и поднимает по Y, чтобы bbox был в положительных координатах.
- `addRowToSelected()` для arc-сектора пересчитывает `maxR` и `offsetX` для нового числа рядов, сдвигает все существующие места на `dx = newOffsetX - oldOffsetX`, добавляет новый ряд через `arcSeatXY`. Старые места остаются на тех же дугах.
- В `draw()` для arc-секторов рисуются полупрозрачные декоративные дуги через `Konva.Arc` — наглядно показывают кривизну.
- `exportSchema()` включает новые поля сектора в JSON.
- Панель формы: `NSegmented` «Прямоугольник / Амфитеатр» + поле «Угол раствора, °» (появляется при arc). Подсказка про 180° = полукруг.
- Высота canvas увеличена до 680px (было 520), чтобы амфитеатр + партер помещались.
- Toast `NToastHost` поднят с `top-20` до `top-32` (128px), чтобы не перекрывал заголовок редактора (хедер админки 64 + заголовок страницы 64).
- Seed-данные теперь два сектора: «Балкон» (амфитеатр, 96 мест) + «Партер A» (прямоугольник, 126 мест), позиция партера = `balcony.y + bbox(balcony).height + 70`.

**Верификация:** typecheck зелёный, build:preview 494 КБ, скриншот `.shots/08c-amphitheatre.png` подтверждает кривизну Балкона + прямой Партер.
