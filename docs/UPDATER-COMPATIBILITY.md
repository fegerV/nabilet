# Матрица совместимости версий NABILET

Документ фиксирует правила, которые проверяются перед обновлением и при восстановлении.

## 1. Версии и каналы

| Поле манифеста | Правило |
|---|---|
| `version` | Релиз должен быть строго обновлением для текущей `config('nabilet.version')` (`ReleaseManifest::appliesTo()`). |
| `channel` | `stable` для боевых установок; иной канал требует явного выбора администратора. |
| `min_php` / `max_php` | Проверяется `ManifestVerifier::verifyPlatform()` до загрузки архива. |
| `artifact_sha256` | Проверка целостности архива. **Не является подтверждением подлинности** — для ленты нужна подпись. |
| `signature` | Обязательна для релизов из ленты; ручная загрузка — отдельная доверенная операция администратора. |

## 2. Совместимость БД

| Ситуация | Разрешено | Действие |
|---|---|---|
| Миграции добавлены (new columns/tables) | да | Применять до снятия режима обслуживания; старый код с новой БД обычно работает. |
| Миграции только переносят данные | да | Проверять на копии реальных данных; сохранять снимок строк в журнале. |
| Удаление колонки/таблицы | только по безопасному плану | Разделять на релизы: сначала код перестаёт пользоваться полем, затем удаление в следующей версии. |
| Изменение типа колонки | нет без теста на копии | Требуется отдельная миграция и проверка VH-данных. |
| Откат после `migrate: done` | **нет** | БД восстанавливается вручную из проверенной копии; автоматический откат запрещён. |

## 3. Политика отката

| Состояние обновления | Откат кода | Откат БД |
|---|---|---|
| `failed` (до замены файлов) | да | не требуется |
| `failed_after_swap`, миграции не применялись | да, автоматически по таймауту | не требуется |
| `done`, миграции не применялись | да, только последний релиз | не требуется |
| `done`/`failed_after_swap`, миграции применены | заблокирован `UPDATE_ROLLBACK_REQUIRES_DB_RESTORE` | только вручную из копии, до возобновления продаж |
| Более старый релиз, после которого были новые | заблокирован `UPDATE_STALE_ROLLBACK` | — |

## 4. Резервные копии

- Максимальный возраст: `NABILET_UPDATE_BACKUP_MAX_AGE_HOURS` (по умолчанию 24).
- Полная копия считается валидной, только если ZIP открывается, не содержит `..`/абсолютных путей и включает `.sql`-дамп; для `.enc` проверяются ключ и HMAC.
- Копия привязывается к `update_id` через `state.json`/журнал.
- Перед боевым восстановлением копия разворачивается в отдельную БД и сверяется количество билетов/заказов.

## 5. Что не гарантируется

- совместимость с версией Android-контролёра старше заявленной в манифесте;
- автоматический откат после возобновления продаж;
- атомарное переключение релизов на хостинге без поддержки symlink-атомарности.
