# ПРАВИЛО: файл пишется вместе со страницами, а не раньше.
# Каждый `Disallow` ниже закрывает раздел, который реально существует
# и не должен попадать в индекс. Если раздел удалён — удалите строку;
# если добавлен служебный — добавьте. «На всякий случай» запрещать
# существующие страницы нельзя: закрытая роботом полезная страница
# теряет и трафик, и внешние ссылки (Google не может их перераспределить).
#
# Чего здесь СОЗНАТЕЛЬНО нет:
#   /event/*     — это и есть SEO-страницы мероприятий, они должны индексироваться
#   /city/*      — посадочные страницы городов (аудит P-12), серверный HTML
#   /venue/*     — посадочные страницы площадок (аудит P-12), серверный HTML
#   /category/*  — посадочные страницы категорий (аудит P-12), серверный HTML
#   /organizer/* — посадочные страницы организаторов (аудит P-12), серверный HTML
#   /artist/*    — посадочные страницы артистов (стратегия SEO, B-1), серверный HTML
#   /            — витрина (каталог)
#   /assets/     — статика Vite, нужна для отрисовки. Запрет не экономит
#                  краулинговый бюджет, но ломает рендеринг постраничных превью.
#
# Строки про /city/*, /venue/*, /category/*, /organizer/* и /artist/* — не «на
# всякий случай». Все они отвечают серверным HTML без JavaScript
# (LandingPageRenderer), поэтому их обход не зависит от сборки витрины; запрет
# закрыл бы ровно тот длинный хвост запросов, ради которого страницы и делались.
# Ссылки пагинации (`?page=N`) запрещать тоже не нужно: страницы за последним
# номером отвечают 404, а не «тонким» документом, поэтому бесконечного перебора
# не возникает.

User-agent: *
Allow: /

# Главное зеркало для Яндекса (стратегия SEO, B-7).
#
# Яндекс при индексации выбирает между `www` и без `www`, между http и https,
# и между доменом и его зеркалами по ряду сигналов; явная директива `Host:`
# снимает эту неоднозначность. Директива действует ТОЛЬКО на бота Yandex —
# Google её игнорирует, а у остальных роботов Яндекса (`YandexImages`,
# `YandexNews`, `YandexMetrika` и т. д.) собственный `User-agent` блок
# срабатывает как уточнение, и они наследуют `Host:` от `User-agent: Yandex`,
# если он объявлен выше. Поэтому здесь стоит именно `Yandex`, а не `*`.
#
# Адрес БЕЗ `www.` намеренно: текущий канонический домен именно такой,
# и `Host: https://nabilet.ru` фиксирует его как предпочтительный. Если
# когда-нибудь добавится алиас `www.`, `Host` нужно будет сменить — но
# смена без явной миграции через 301 в nginx НЕ должна происходить молча.
#
# ПОЧЕМУ НЕ `Sitemap:` ТУТ ЖЕ. Sitemap для Yandex уже объявлен в общей
# секции `User-agent: *` ниже, и `Host:` на неё не влияет.
User-agent: Yandex
Host: https://nabilet.ru

# Админ-панель. Токен в localStorage, но URL-ы утекают через логи рефереров
# и скриншоты; индексировать их незачем.
Disallow: /admin
Disallow: /admin/

# (корзина, номер заказа, сумма) и не имеют уникального контента.
Disallow: /checkout
Disallow: /checkout/
Disallow: /payment/
Disallow: /cart

# скоупится по заголовку X-Cart-Token. Это публичный по дизайну эндпоинт,

Disallow: /tickets
Disallow: /api/v1/tickets
Disallow: /api/v1/my-tickets
Disallow: /api/v1/me/

# Установщик. Одноразовый pre-auth мастер; после создания storage/install.lock

Disallow: /install
Disallow: /install/

# API целиком. Отдаёт JSON (не HTML), индексация бессмысленна, а ответы
# с ошибками (§66 envelope) в индексе выглядят как «мусорный» контент.
# Исключений больше нет: раньше внутри /api/v1 жила карта сайта, и этот файл
# одновременно запрещал адрес и объявлял его в директиве `Sitemap`. Карта
# переехала в корень (аудит P-10a), поэтому запрет стал безоговорочным.
Disallow: /api/v1/

# Карта сайта. Корневой `/sitemap.xml` — адрес, по которому Яндекс и Google
# ищут карту по умолчанию, даже не читая этот файл. Путь именно такой потому,
# что карта сайта — не часть API: она не версионируется, не требует JSON-
# конверта §66 и адресуется роботом, а не клиентом.
#
# Карта-индекс ссылается на семь разделов: sitemap-events, sitemap-static,
# sitemap-venues, sitemap-cities, sitemap-categories, sitemap-organizers (аудит
# P-12) и sitemap-artists (стратегия SEO, B-1). Указывать их здесь по
# отдельности не нужно: индекса достаточно.
# Карта событий, кроме того, разбита на страницы (`?page=N`) — их перечислять
# здесь тем более не нужно.
#
# ПОЧЕМУ ОТНОСИТЕЛЬНЫЙ ПУТЬ, А НЕ АБСОЛЮТНЫЙ (SEO-аудит P-10b).
# Спецификация действительно ожидает полный URL, и аудит справедливо на это
# указал. Абсолютный адрес здесь означал бы одно из двух, и оба хуже текущего:
#
#   1. Захардкодить домен. Тогда файл, лежащий в репозитории, на каждом
#      стенде и в каждой локальной копии объявлял бы картой сайта ПРОДАКШЕН.
#      Краулер, дошедший до тестового окружения, получил бы чужую карту.
#   2. Генерировать файл на деплое. Это ещё один шаг, который можно не
#      выполнить; невыполненный шаг оставляет ровно тот же файл, но с иллюзией,
#      что «уже настроено».
#
# Компромисс — относительный путь: Google и Яндекс разрешают его относительно
# хоста, с которого прочитан robots.txt, то есть на каждом окружении он
# указывает на СВОЮ карту. Это отклонение от буквы спецификации, выбранное
# сознательно, и оно зафиксировано здесь, а не оставлено как недосмотр.
#
# Переезд выполнен (P-10a). Карты зарегистрированы в
# `app/Modules/Seo/routes/web.php`; старые адреса `/api/v1/sitemap*.xml`
# отвечают 301 в nginx (а не маршрутом Laravel: на api-группу навешан
# `ForceJsonResponse`, и редирект превратился бы в JSON-конверт).
#
# Правки OpenAPI не потребовалось: ни `docs/openapi.yaml`, ни
# `nabilet_core_spec/openapi.yaml` карты сайта не описывают — они не являются
# частью публичного API-контракта, а предыдущая запись об обратном была
# неточной. Проверено grep по обоим файлам.
Sitemap: /sitemap.xml

# Содержимое карт кешируется на час (SitemapService::CACHE_TTL). Это значит,
# что событие, опубликованное сразу после сборки, появится в карте с задержкой
# до часа. Для карты сайта это нормально: краулер всё равно не переобойдёт её
# мгновенно, а страница события доступна сразу — карта лишь подсказка.
