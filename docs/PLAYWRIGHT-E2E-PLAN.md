# План Playwright E2E для NABILET

Статус: **план и критерии готовности**, инфраструктура ещё не подключена к CI (см. `docs/audit/STABILIZATION-REPORT.md`).

## 1. Принципы

- Тесты работают только на отдельном test-стенде с отдельной БД; рабочая БД и платёжные ключи не используются.
- У каждого теста свои seed-данные и cleanup; параллельность ≥2 воркеров только при изолированных БД.
- Скриншоты editor/public map сохраняются как артефакты CI; visual snapshot имеет допуск на сглаживание/шрифты.
- Успешная сборка не считается успешным E2E.

## 2. Инфраструктура

1. Добавить `@playwright/test` в `devDependencies`, `playwright.config.ts` с `baseURL` test-стенда и `webServer` для локального прогона.
2. Отдельный `.env.e2e`: `APP_ENV=testing`, тестовая БД, `NABILET_TEST_PAYMENTS=1`, demo-провайдер оплаты.
3. CI-job `e2e` после `phpunit`/`frontend`: поднять MySQL, применить SQL-бандл, собрать hosting-релиз, развернуть в каталоге, emulation shared hosting, запустить Playwright, загрузить screenshots/trace как artifacts.
4. Стабильные `data-testid` на ключевых элементах: installer, login, venue form, hall editor canvas, publish, event form, seat map, checkout, ticket PDF, checker.

## 3. Сценарий 1 (основной цикл)

Чистая установка → вход администратора → создание площадки → импорт схемы зала (фикстура СурГУ) → подтверждение расхождений → публикация → создание мероприятия и сеанса → настройка шаблона билета → покупка в тестовом режиме → выпуск билета → скачивание PDF → декодирование QR → возврат билета.

Проверки: номер/сектор/ряд/место совпадают с выбранными; QR декодируется в подписанный payload; после возврата билет не проходит проверку.

## 4. Сценарий 2 (обновление и восстановление)

Установить предыдущий релиз → заполнить тестовыми коммерческими данными → создать проверенную резервную копию → обновление → сверка заказов/билетов/цен → безопасное аварийное восстановление из копии → smoke-проверки витрины и QR.

Проверки: данные покупателей не потеряны; старый код не работает с несовместимой БД; maintenance mode снимается только после успешных smoke-тестов.

## 5. Критерии подключения к CI

- `playwright test` проходит 2+ прогона подряд без флаков;
- screenshots и trace загружаются как artifacts;
- визуальные регрессии имеют зафиксированный tolerance и не ломаются на шрифтах/anti-aliasing;
- E2E не имеет доступа к рабочим платёжным ключам.
