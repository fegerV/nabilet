# ПРАВИЛО: файл пишется вместе со страницами, а не раньше.
# Каждый `Disallow` ниже закрывает раздел, который реально существует
# и не должен попадать в индекс. Если раздел удалён — удалите строку;
# если добавлен служебный — добавьте. «На всякий случай» запрещать
# существующие страницы нельзя: закрытая роботом полезная страница
# теряет и трафик, и внешние ссылки (Google не может их перераспределить).
#
# Чего здесь СОЗНАТЕЛЬНО нет:
#   /event/*     — это и есть SEO-страницы мероприятий, они должны индексироваться
#   /city/*      — посадочные страницы городов (аудит P-12), серверный HTML
#   /venue/*     — посадочные страницы площадок (аудит P-12), серверный HTML
#   /category/*  — посадочные страницы категорий (аудит P-12), серверный HTML
#   /organizer/* — посадочные страницы организаторов (аудит P-12), серверный HTML
#   /            — витрина (каталог)
#   /assets/     — статика Vite, нужна для отрисовки. Запрет не экономит
#                  краулинговый бюджет, но ломает рендеринг постраничных превью.
#
# Строки про /city/*, /venue/*, /category/* и /organizer/* — не «на всякий
# случай». Все они отвечают серверным HTML без JavaScript (LandingPageRenderer),
# поэтому их обход не зависит от сборки витрины; запрет закрыл бы ровно тот
# длинный хвост запросов, ради которого страницы и делались. Ссылки пагинации
# (`?page=N`) запрещать тоже не нужно: страницы за последним номером отвечают
# 404, а не «тонким» документом, поэтому бесконечного перебора не возникает.

User-agent: *

Disallow: /install/

# API целиком. Отдаёт JSON (не HTML), индексация бессмысленна, а ответы
# с ошибками (§66 envelope) в индексе выглядят как «мусорный» контент.
# ИСКЛЮЧЕНИЕ: sitemap.xml живёт ВНУТРИ /api/v1 (роуты модуля Seo подключены
# централизованно из routes/api.php) и его запрещать нельзя ни в коем случае —
# иначе поисковик не сможет прочитать карту сайта.
Disallow: /api/v1/

# Карта сайта. Путь именно такой: модуль Seo подключён в API-группу, поэтому
# схема доступна на /api/v1/sitemap.xml, а не на /sitemap.xml.
#
# Карта-индекс ссылается на шесть разделов: sitemap-events, sitemap-static,
# sitemap-venues, sitemap-cities, sitemap-categories и sitemap-organizers
# (аудит P-12). Указывать их здесь по отдельности не нужно: индекса достаточно.
# Карта событий, кроме того, разбита на страницы (`?page=N`) — их перечислять
# здесь тем более не нужно.
#
# ПОЧЕМУ ОТНОСИТЕЛЬНЫЙ ПУТЬ, А НЕ АБСОЛЮТНЫЙ (SEO-аудит P-10b).
# Спецификация действительно ожидает полный URL, и аудит справедливо на это
# указал. Абсолютный адрес здесь означал бы одно из двух, и оба хуже текущего:
#
#   1. Захардкодить домен. Тогда файл, лежащий в репозитории, на каждом
#      стенде и в каждой локальной копии объявлял бы картой сайта ПРОДАКШЕН.
#      Краулер, дошедший до тестового окружения, получил бы чужую карту.
#   2. Генерировать файл на деплое. Это ещё один шаг, который можно не
#      выполнить; невыполненный шаг оставляет ровно тот же файл, но с иллюзией,
#      что «уже настроено».
#
# Компромисс — относительный путь: Google и Яндекс разрешают его относительно
# хоста, с которого прочитан robots.txt, то есть на каждом окружении он
# указывает на СВОЮ карту. Это отклонение от буквы спецификации, выбранное
# сознательно, и оно зафиксировано здесь, а не оставлено как недосмотр.
#
# Переезд карты на /sitemap.xml (P-10a) требует смены владельца роутов: модуль
# Seo обязан жить в API-группе (tools/verify-route-ownership.php), поэтому
# корневой адрес — это отдельное решение с правкой nginx, обоих файлов OpenAPI
# и этой строки. Пока он не принят, путь остаётся внутри /api/v1 и исключён из
# общего запрета выше.
Sitemap: /api/v1/sitemap.xml

# до часа. Для карты сайта это нормально: краулер всё равно не переобойдёт её
# мгновенно, а страница события доступна сразу — карта лишь подсказка.
