# Конструктор схем залов и цены на места

Документ описывает, как устроена схема зала, что такое ценовые группы и как
задавать цены для каждого концерта (сеанса). Исправления от 2026-11-18
войдут в следующий релиз (после v1.4.0).

## 1. Где что живёт

| Уровень | Что хранит | Где правится |
| --- | --- | --- |
| Площадка (`venues`) | адрес, город, залы | `/admin/venues`, карточка площадки → «Схема зала» |
| Зал (`halls`) | имя, привязка к площадке | создаётся вместе с площадкой или через `/api/v1/halls` |
| Версия схемы (`hall_schema_versions`) | геометрия и **базовые цены** | конструктор `/admin/halls/{id}/editor` |
| Сеанс (`sessions`) | концерт, дата, зал, версия схемы | `/admin/sessions` → форма сеанса |
| Инвентарь (`inventory_items`) | продаваемые места и **цены этого концерта** | `/admin/sessions/{id}/prices` |

Геометрия (`sectors`, `hall_rows`, `seats`, `standing_zones`) принадлежит
**версии схемы**, а не сеансу. Второй и последующий сеанс того же зала
переиспользуют её. Сеансу принадлежат только строки инвентаря с ценами,
статусами и вместимостью.

## 2. Ценовые группы в схеме зала

Отдельной сущности «ценовая группа» нет, и это намеренно: группа — это
**совокупность мест с одинаковой действующей ценой**. Действующая цена
вычисляется по правилу **место → ряд → сектор** (класс
`Nabilet\Modules\Venues\Domain\SchemaPrice`, клиентское зеркало —
`effectiveSeatPrice()` в `resources/js/lib/hall.ts`):

1. `seat.priceMinor` — индивидуальная цена места (VIP, отдельный стол, отдельный ряд);
2. `sector.rowPrices[номер_ряда]` — цена ряда;
3. `sector.priceMinor` — цена сектора по умолчанию.

Для стоячей зоны цена лежит в самом объекте схемы (`priceMinor`) и попадает
в `standing_zones.price_amount`.

Где видны группы:

- в конструкторе — цвет мест и легенда справа (`buildSeatPricePalette`):
  один цвет на одну уникальную цену;
- в витрине — чипы ценовых категорий у карты зала (`CoordSeatMap.vue`) и
  подписи «от N ₽» у секторов. Группы вычисляются из **инвентаря сеанса**,
  поэтому цены концерта сразу видны покупателю.

**Единицы.** В UI все поля цен — **рубли** (целое число). В payload схемы,
в БД (`hall_rows.price_amount`, `seats.price_amount`,
`inventory_items.price_amount`) и в API — **копейки**. Преобразование живёт
в `resources/js/lib/money.ts` (`rubToMinor` / `minorToRub`). Поле «Цена по
умолчанию» в форме «Новый сектор» тоже в рублях — исправление 2026-11-18:
раньше оно подписывалось «коп.» и превращало введённые 1500 ₽ в 15 ₽.

## 3. Что умеет конструктор (проверенный список)

Проверены все группы функций редактора `HallEditorPage.vue`:

- **Генератор сектора**: прямоугольная сетка и амфитеатр (дуги), число рядов
  и мест, число VIP-рядов сверху, шаг мест/рядов; банкетный стол создаётся
  отдельным инструментом — цена задаётся один раз на весь стол;
- **Ряды**: выделить, добавить после выбранного (`insertRowAfter`), удалить
  с перенумерацией (`deleteRow`), перенумеровать места, переопределить цену
  ряда. `rowPrices` пересчитывается при вставке/удалении ряда;
- **Места**: одиночная установка/перетаскивание с привязкой к ближайшему
  ряду, рамка выделения, «выделить все», выравнивание по краю/центру,
  распределение, дублирование, удаление, смена типа (обычное / VIP /
  маломобильные), перенос в другой сектор, **индивидуальная цена места**.
  При перетаскивании по вертикали место действительно **пересаживается** в
  другой ряд: `seat.row` пересчитывается по Y для сетки и по радиусу для
  амфитеатра, номера в затронутых рядах пересобираются;
- **Статические объекты**: сцена, вход, подписи, стоячие зоны (цена + ёмкость),
  столы-декорации; блокировка от случайного перетаскивания;
- **Фон**: загрузка изображения, позиция/размер/прозрачность, блокировка;
- **История**: undo/redo со снимками до изменения (в т.ч. до перетаскивания),
  отмена пустого шага, если ничего не изменилось;
- **Автосохранение**: отложенная запись черновика, сброс при уходе со страницы,
  показ ошибок валидации сервера в понятном виде;
- **Публикация**: опубликованная версия иммутабельна (изменения создают новую
  версию), кнопка «Новая версия» создаёт черновик из опубликованной;
- **Масштаб**: zoom, «вписать», «вписать по содержимому», горячие клавиши;
- **Адаптив**: панели слева/справа статичны только при ширине контейнера
  ≥ 1280 px, на узких экранах — оверлей поверх холста;
- **Импорт/экспорт**: для экспорта схемы в файл используется тот же
  сериализатор, что и для автосохранения; загрузка поддерживает редакторский
  и БД-форматы.

## 4. Как установить цены на места для нового мероприятия

Порядок (одна схема зала, разные цены на каждый концерт):

1. **Площадка и зал.** `/admin/venues` → создать площадку (зал «Основной зал»
   создаётся автоматически). Карточка площадки → колонка «Схема зала» →
   «Открыть»/«Создать».
2. **Схема.** В конструкторе задайте цену сектора (₽), при необходимости цены
   отдельных рядов и мест, стоячую зону. Это **базовая сетка зала**, общая для
   всех дат. Опубликуйте схему — сеанс нельзя создать без опубликованной версии.
3. **Мероприятие.** Создайте событие в `/admin/events`.
4. **Сеанс.** `/admin/sessions` → «Создать», выберите мероприятие, площадку,
   зал (версия схемы подставится последней опубликованной), дату и время.
   Инвентарь мест создаётся автоматически из схемы с базовыми ценами.
5. **Цены концерта.** В списке сеансов нажмите «Цены» у нужной даты —
   `/admin/sessions/{id}/prices`. Заполните нужные строки (рубли), остальные
   оставьте пустыми — они не будут изменены. Оставьте галочку **«Только этот
   сеанс»** включённой: цены запишутся в инвентарь этого концерта, а сетка
   зала останется базовой. Нажмите «Применить».
6. **Проверка.** Откройте витрину события → карту мест: легенда и чипы должны
   показывать новые цены. Повторите шаги 4–5 для следующей даты — каждый
   сеанс получит свои цены, предыдущие не изменятся.

Что важно:

- пустое поле в таблице цен — «не менять»;
- 0 ₽ — допустимая цена ряда (бесплатный ряд);
- холды и проданные билеты **никогда** не переоцениваются — контракт покупки
  не меняется задним числом; открытые корзины пересчитываются автоматически;
- места со своей ценой в схеме (VIP внутри ряда) ценой ряда **не затираются**:
  действует приоритет «место → ряд → сектор». В ответе сервера их число
  возвращается в `items_kept_individual` и показывается в сводке;
- если снять «Только этот сеанс», цены дополнительно запишутся в
  `hall_rows`/`standing_zones` и унаследуются будущими сеансами этого зала —
  это режим «изменить базовую сетку зала».

## 5. API цен

- `PATCH|POST /api/v1/inventory/sessions/{sessionId}/prices` (auth + staff):
  `{"rows":[{"row_id":12,"price_amount":250000}, …],"session_only":true}`.
  Для стоячих зон вместо `row_id` — `standing_zone_id`. Ответ содержит
  `rows_updated`, `items_updated`, `items_kept_individual`,
  `cart_items_updated`, `carts_recalculated`, `session_only`.
- `GET /api/v1/inventory?session_id=N` — инвентарь сеанса (источник витрины и
  формы цен).
- `POST /api/v1/halls/{publicId}/schema-versions/draft` — черновик новой версии;
  публикация создаёт неизменяемую версию.

Несовпадения, найденные и исправленные при аудите 2026-11-18:

1. форма «Новый сектор» принимала копейки, остальные поля — рубли;
2. смена цены ряда затирала индивидуальные цены мест в текущем сеансе;
3. индивидуальная цена места из rows-формата (`price_amount`) игнорировалась
   при генерации инвентаря;
4. валидатор схемы отвергал ряд, целиком состоящий из мест со своими ценами,
   и не учитывал цену места при проверке продаваемости;
5. после установки `/install` оставался доступен (302/403), а `info.php` —
   открытым.
