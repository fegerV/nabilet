## 2. Достоверность

Классификация не заменяет ручную проверку:

- `yandex_exact` — место/координата/цена присутствовали в исходном hallplan;
- `reconstructed` / `inferred` — местоположение восстановлено по анкерам, донорскому ряду или кольцу стола;
- `unknown` — цена/вместимость неизвестны и **не выдаются за подтверждённые**;
- `import.exactness` — `exact` только если нет реконструированных мест, неизвестных цен и неподтверждённых зон.

Импорт **не переносит** продажи, брони и статусы мест сторонней системы: `availableSeatCount` используется лишь как оценочный остаток standing-зоны и помечается как неподтверждённый.

## 4. Оставшиеся ограничения

1. Пошаговый мастер импорта (источник → загрузка → анализ → конвертация → предпросмотр → сравнение → правки → черновик) **не реализован как отдельный wizard**: текущий однократный импорт дополнен structured report и сравнением с черновиком (`compare`), но без пошагового UI.
2. Нет синхронизированного просмотра исходной и результирующей геометрии с визуальной маркировкой восстановленных мест на холсте.
3. Нет браузерных E2E/визуальных регрессионных тестов импорта.
4. Автосохранение после импорта по-прежнему может изменить черновик без отдельного подтверждения пользователя (защита ревизий на сервере есть).
5. Публикация по-прежнему отклоняет standing-зоны с `capacity=0` и `priceMinor=0` — это осознанный барьер; черновик теперь сохраняет такие зоны, и администратор подтверждает тариф через редактор (Y-10).
6. `source_id` детерминирован для одинакового входа, но не устойчив к перестановке исходных массивов (зависит от порядка), и не хранит cross-version маппинг.
7. Тайм-ауты/глубина JSON на сервере ограничены числом уровней/мест/координат; отдельного лимита глубины вложенности нет.

Ни один пункт не помечен как решённый без теста или изменения кода.
