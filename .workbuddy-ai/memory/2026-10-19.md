## Зал «Вавилон»: геометрия столов переделана с нуля

Жалоба: в конструкторе места стояли «как попало», не как на витрине Яндекса.

**Причина.** `tools/hallplan-to-schema.php` в режиме столов собирал каждый
стол по шаблону ПЕРВОГО стола той же вместимости, привязанному к первому
известному месту. Шаблон чужой ориентации поворачивал кольцо, привязка
съезжала — у 18 столов с ≥3 известными местами центр уезжал до 265 px
(в среднем 130). Плюс `$resolveOverlap` дёргал места по y на 1 px, добивая
кольца.

**Что сделано.**
- Режим столов переписан: окружность по МНК по известным местам, углы
  известных сохраняются, пропуски достраиваются равномерно; для 0–2 известных
  мест — донор той же вместимости (центр по смещению «анкер → центр»,
  поворот по двум известным). Детали — `docs/YANDEX-AFISHA-HALLPLAN.md` §6.1.
- `$SCALE = 1.2`: у Яндекса соседние места кольца стоят по диагонали 14×14, а
  валидатор запрещает `|dx|<16 && |dy|<16`. Масштаб равномерный.
- Цена целиком распроданного стола — у ближайшего стола с ценой (было: первая
  цена уровня → 5000 ₽ половине зала при реальных 3000–4500).
- Стоячие зоны: раскладка по центру зала от admission-точек (было жёстко
  (620,640) — наезжало на столы), ширина ∝ √вместимости.
- Флаг `--draft <versionId>` — перезапись существующего черновика.

(version id 26): 52 стола, 259 мест, 0 наложений, мин. шаг 17 px, все 94

## Ряды без якорей: перенос соседнего ряда + контур как арбитр (вечер)

Пользователь прислал четыре источника (`Ледовый Дворец спорта.json`,
`Нефтяник.json`, `Вавилон.json`, `hallplan.json` = СурГУ) и скриншоты виджета.
Проверка показала: у «СурГУ» (hall 15) схема v4 была не просто неточной, а
нарисованной ДРУГОЙ моделью — все ряды горизонтальные с шагом 20.7, хотя в
источнике ряды 9/12/13 идут диагональю −8 px на место.

**Что даёт Яндекс для достройки.** `levels[].outline` — SVG-путь контура
уровня, независимый от мест (есть, даже когда всё распродано). `rows[].xCoord/
yCoord` — координата ПЕРВОГО места (проверено на всех четырёх залах). У СурГУ
11 из 16 рядов партера без единого продаваемого места.

**Модель (итоговая).** Ряды с ≥2 анкерами — кусочно-линейная интерполяция,
координаты анкеров байт-в-байт. Ряд без анкеров — копия ближайшего ряда с
геометрией, перенесённая так, чтобы его первое место легло на известную точку
(вектор = радиальное смещение, шаг между рядами сохраняется сам). Если перенос
вылезает за `outline`, а прямая от первого места — нет, берётся прямая
(задние ряды прямоугольной части СурГУ).

**Анкеры неприкосновенны.** Все координаты `seats[]` попадают в `$occupied`
ДО раскладки; `$resolveOverlap` двигает только достроенные места. Было
наоборот — достроенный ряд наезжал на соседний и утягивал реальные места
(Ледовый: 70 px, СурГУ ряд 12: 42 px). Отвергнутые варианты: окружность по
МНК с общим центром уровня (ряды СурГУ — трапеции, а не дуги; дуга уводила
ряд 11 на 95 px вверх и он бился о ряд 12) и «пролёт вместо шага» (растягивало
11-местный ряд 1 в 3 раза).

**Проверки (новые скрипты).** `.shots/hallplan-outline-check.mjs` — контур
уровня → полигон, перенос в систему схемы (МНК по местам), счёт мест вне
контура + картинка. `.shots/hallplan-schema-diff.mjs` — расхождение координат
и наложения. Итог: СурГУ 512 мест, 0.0 px (163/163), вне контура 0, шаг 16;
Нефтяник 1073, 0.0 px (750/750), 0; Ледовый 2181, 0.0 px (675/675), 1.

## Цены для конкретного мероприятия: где и чем (вечер, после hallplan)

Вопрос владельца «как менять цены на места для определённого мероприятия».
Ответ по коду и живому стенду:

- **Три уровня.** (1) Схема зала: `sector.priceMinor` → `sector.rowPrices[ряд]` →
  `seat.priceMinor` (место сильнее ряда, ряд сильнее сектора) — конструктор зала,
  влияет только на БУДУЩИЕ сеансы. (2) Сеанс: при генерации инвентаря цена
  материализуется в `inventory_items.price_amount`. (3) Переопределение сеанса:
  `PATCH /api/v1/inventory/sessions/{id}/prices` → `InventoryService::updateRowPrices()`.
- **UI:** `/admin/sessions/{id}/prices` (`AdminSessionPricesPage.vue`), входы —
  «Сеансы» → «Цены» (`AdminSessionsPage`) и карточка мероприятия → сеанс → «Цены»
  (`AdminEventFormPage`). Подсказка про уровни — `AdminHelpPage` → блок «prices».
- **Семантика (проверено на сеансе 20, Вавилон):** обновляются только свободные
  позиции (`available_quantity = capacity`); холды и `sold` сохраняют цену;
  активные корзины пересчитываются; **`hall_rows.price_amount` тоже
  перезаписывается** → следующий сеанс этого зала унаследует новую цену (это
  неявный побочный эффект «только для этого показа»). Витрина «от N ₽» считается
  на лету (MIN по `inventory_items`, кеша нет).
- **Ограничение:** по отдельному месту цена на уровне сеанса не задаётся — только
  ряд/стоячая зона. VIP-место — только через схему (новый сектор или `seat.priceMinor`).
- **Починен баг подписи ряда.** `AdminSessionPricesPage` строила подпись из
  `seat.label`; в залах-«столах» (Вавилон) у каждого стола свой ряд «1», и все 54
  строки выглядели как «Ряд 1 Место 1» — править цену приходилось наугад. Теперь
  «Стол 44 · ряд 1» из `seat.sector_name` + `seat.row_number` (контроллер их уже
  отдаёт), натуральная сортировка по сектору и номеру ряда, имя стоячей зоны из
  `standing_zone.name`, диапазон «сейчас» для рядов с разными ценами. Файлы:
  `resources/js/pages/admin/AdminSessionPricesPage.vue`, `resources/js/lib/inventory.ts`.
  `vue-tsc` чист, `dist/` пересобран. Скрипт скриншота — `.shots/session-prices.mjs`
  (`viewport` в argv — только видимая область, иначе 54 ряда нечитаемы).
- **Грабли проверки:** guard админки требует не только `nabilet_admin_token`, но и
  `nabilet_admin_user` с ролью admin/manager (`auth.ts::isAdminSession`) — без
  второго ключа headless-браузер уезжает на логин.

## Ценовая лесенца «ближе к сцене — дороже» + изоляция сеансных цен (ночь)

Закрыл два открытых вопроса измини-сессии: побочный эффект перезаписи сетки зала
и ручной ввод 52 столов.

**1. `session_only` — цены только для этого сеанса.**
- `InventoryService::updateRowPrices($sessionId, $rows, bool $sessionOnly = false)`
  (дефолт `false` = старое поведение, обратная совместимость). При `true` НЕ
  пишем в `hall_rows.price_amount` и `standing_zones.price_amount` — только
  `inventory_items` свободных позиций + синхронизация активных корзин. В ответ
  добавлен ключ `session_only`, чтобы режим был виден в API, а не только по коду.
- `UpdateRowPricesRequest`: новое правило `session_only` (`sometimes|boolean`),
  докблок с примером и рекомендацией для разовых цен под конкретный концерт.
- `InventoryController::updatePrices` пробрасывает флаг.
- Гейт проверки ряда («ряд относится к сессии») НЕ менялся — он смотрит в
  `inventory_items`, а туда пишем и в `session_only` режиме тоже, так что админ
  одного города не тронет цены чужого зала.

**2. `tools/vavilon-price-ladder.php`** — CLI-генератор лесенки.
- Вход: координаты столов из `schema_json` (канвас-формат: `seats[]` или
  `rows[].seats[]` + смещение `sector.x/y`). Центр стола = среднее координат мест.
- Точка «фронта сцены»: по умолчанию — вместимостно-взвешенный центр танцпола
  (`staticObjects` kind=standing; в схеме Вавилона объекта сцены НЕТ).
  Переопределяется `--stage-x/--stage-y`, альтернатива `--ref centroid`.
- Тиры `--tiers N`: сортировка по расстоянию, линейная цена между `--max` и
