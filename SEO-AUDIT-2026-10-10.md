## 1. Таблица обнаруженных SEO-проблем

ID: P-nn.severity: 🔴 критично / 🟠 высоко / 🟡 средне / 🔵 низко.

### Что уже сделано хорошо (фиксировать и не сломать)

- Server-side unique title/description/canonical/OG/JSON-LD именно для страниц событий, с историей исправленных багов в комментариях (startDate из sessions, absolute og:image, pruneEmpty для JSON-LD).
- `X-Robots-Tag` как императивный запрет для служебных путей (грамотнее одного robots.txt).
- 301 с укороченного URL на канонический.
- `noindex, noarchive` автоматически для scheduled/cancelled; согласованность с `publiclyVisible()` в sitemap.
- JSON-LD: `EventCompleted`/`EventCancelled`/`SoldOut`/`OutOfStock` замаплены; пустые поля вычищаются (валидатор Google не ругается на `""`).
- robots.txt написан по принципу «правила вместе со страницами», с обоснованием каждого Disallow.
- Экранирование `<`/`>` в JSON-LD (защита от XSS через structured data).
- lastmod/priority по статусу, разбиение карты по 50k URL.

## 4. Регрессионные SEO-проверки для автотестирования

Рекомендуемый слой: PHPUnit Feature (уже есть инфраструктура `tests/Feature`) + периодический краулер-скрипт (`qa-scripts/`).

### A. Маршруты и статусы (Feature-тесты)
1. `GET /event/{slug}` без publicId → **301**, Location == канонический URL.
2. `GET /event/{slug}/{correctId}` → **200**, Content-Type text/html.
3. `GET /event/{slug}/{wrongId}` → **301** на канонический *(поймает P-15 после фикса)*.
4. `GET /event/unknown-slug` → **404**.
5. draft → 404; archived → (после P-01) 200+noindex или 301, **не 404**; cancelled/scheduled → 200 + `<meta name="robots" content="noindex, noarchive">`; published/completed → 200 **без** noindex.
6. Событие с `canonical_url` вне белого списка доменов → canonical игнорируется *(P-14)*.
7. Отсутствие `dist/index.html` → ответ **503**, не 200 *(P-13)*.
8. Смена slug через API → в `redirects` появилась запись `старый → новый, 301`; `GET старый` → 301 *(P-02)*.
9. Middleware-редиректы: запись в `redirects` действительно обслуживает запрос *(P-02)*.

### B. Метаданные страницы (парсинг HTML ответа)
10. `<title>` уникален между любыми двумя событиями; длина ≤ 70.
11. `meta[name=description]` присутствует, 70–160 символов, уникален.
12. Ровно один `<link rel=canonical>`; он абсолютный, https, совпадает с URL sitemap-записи этого события.
13. `og:title`, `og:description`, `og:url`, `og:image` присутствуют; `og:image` — абсолютный URL; HEAD-запрос к og:image → 200 и image/*.
14. Для completed — title/description содержат маркер прошедшего времени *(P-05)*.

### C. Структурированные данные
15. Валидность JSON: `json_decode` блока ld+json succeeds; `@type == Event`.
16. Обязательные поля non-empty: name, startDate, endDate, location.name, organizer.name, image[0].
17. `startDate` соответствует ближайшему сеансу (для завершённого — последнему прошедшему).
18. `eventStatus` маппится: published→EventScheduled, completed→EventCompleted, cancelled→EventCancelled.
19. `offers.price > 0` для платных событий и равен min цене inventory; `priceCurrency == RUB` *(P-07)*; `offers.url` резолвится (не 404/500) *(P-08)*.
20. Ни одного значения `""` или `null` в JSON-LD (regression на `pruneEmpty`).
21. BreadcrumbList: первая и последняя позиция == canonical текущей страницы *(когда появится, P-09)*.
22. Строка `</script>` в описании события не ломает страницу (escape `\u003C`).

### D. Sitemap / robots
23. `GET /api/v1/sitemap.xml` → 200, valid XML, `<sitemapindex>`; дочерние loc отвечают 200.
24. Каждая `<loc>` из sitemap-events отвечает **200** и её canonical == loc (консистентность sitemap↔страниц — ловит P-14 класс ошибок).
25. В sitemap **нет** draft/scheduled/cancelled/archived; **есть** все published+completed.
26. `lastmod` формата ISO8601 с таймзоной.
27. robots.txt: `Sitemap:` абсолютный URL; ни один Allow-раздел не закрыт Disallow противоречиво; `/event/` не запрещён.
28. Пагинация sitemap: при >50k записей index ссылается на все страницы (unit-тест с моком счётчика).

### E. Каталог / дубли (краулер-скрипт)
29. Обход всех внутренних ссылок главной+страниц событий: 0 ссылок на 4xx; 0 цепочек редиректов длиной >2.
30. GET `/api/v1/events` без параметров не содержит объектов со status=draft/scheduled *(P-04)*.
31. Hash-URL каталога (`/#/?city=...`) не попадают в sitemap и не имеют серверных двойников без canonical.
32. Дедупликация: множество canonical всех 200-ответов `/event/*` == множеству loc sitemap.

### F. Локализация / соцсети
33. Если включён второй locale: каждая страница содержит пару взаимных hreflang + x-default *(P-11)*; иначе — тест пропускается (не создавать ложных требований).
34. `<html lang>` соответствует языку контента.

## 5. Резюме оценки жизненного цикла страницы события

| Фаза | Текущее поведение (код) | Оценка |
|---|---|---|
| Черновик (draft) | 404, нет в sitemap | ✅ корректно |
| Scheduled (будущая публикация) | 200 + noindex, нет в sitemap | ✅ корректно |
| Публикация/продажи (published) | 200, индексируется, JSON-LD EventScheduled+InStock | ✅ база верна; ❌ offers с price=0 (P-07) |
| Отмена (cancelled) | 200 + noindex, EventCancelled/OutOfStock | 🟡 разметка верна, видимый HTML не отражает статус (P-17) |
| Завершение (completed) | 200, индексируется, EventCompleted/SoldOut | 🟠 контент всё ещё «продающий», нет перелинковки (P-05); автопереход отсутствует (P-06) |
| Архив (archived) | **404** | 🔴 потеря индексной страницы без редиректа (P-01, P-02) |
| Удаление | физический DELETE → 404 JSON | 🟡 нет 410, нет следа в redirects (P-24) |

**Главный вывод:** архитектурный каркас SEO (server-rendered мета + JSON-LD для событий) реализован добросовестно и с защитой от известных ловушек, но жизненный цикл обрывается на финальной стадии (архив = 404 при незадействованной таблице редиректов), а ценность страницы после завершения события не переосмысляется. Наиболее дешёвые по трудозатратам и наибольшие по эффекту правки — P-01/P-02 (сохранение индексной базы) и P-07 (корректные цены в разметке).
