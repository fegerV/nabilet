# Известные ограничения (честный список)

Статус на 2026-11-27. Пункты не скрываются и не выдаются за решённые.

1. **Ручная приёмка Timeweb не выполнена.** Все проверки локальные/CI.
   Конкретная версия PHP/MySQL аккаунта, Handler PHP в `.htaccess`, cron,
   HTTPS и реальные ключи неизвестны до обратной связи владельца.
2. **MySQL 5.7 degraded.** CHECK-ограничения и триггеры на 5.7 не исполняются;
   уникальность, транзакции и PHP-правила работают. Для коммерческих продаж
   нужен MySQL 8.0+.
3. **Публичный ключ не внесён на целевом сайте.** Мастер 1.16.3 умеет безопасно
   записать `NABILET_UPDATE_PUBLIC_KEY` и HTTPS-адрес ленты; приватный ключ не
   принимается и не хранится на сайте. В CI он лежит в секрете
   `NABILET_UPDATE_PRIVATE_KEY_PEM`. Без публичного ключа лента отвергнет
   манифест; ручная загрузка по SHA-256 работает независимо от подписи.
4. **Обновление проверено локально, но не на хостинге.** Переход с неизменного
   оригинального архива 1.16.1 на 1.16.2 дошёл до `done` без ручной подмены
   файлов; данные покупателя сохранены. Прерванное обновление корректно
   переводится в `failed_after_swap`, а откат кода блокируется после начатых
   миграций — требуется восстановление БД из копии. Реальное восстановление
   логического дампа на отдельной БД выполнено и сверено (99 базовых таблиц).
   Команда `backup:run` не прогонялась: на машине нет `mysqldump`.
5. **AUD-023:** публичные медиа отдаются статически по `/storage/...` без
   подписанных URL TTL. Смена схемы — изменение публичного контракта витрины,
   требует решения владельца.
6. **Браузерный E2E покрыт только сценарием чистого стенда.** Он подключён к
   релизному workflow, но локально не выполнялся: песочница браузера в этой
   среде запрещает обращение к loopback (`ERR_NETWORK_ACCESS_DENIED`). Более
   сложные сценарии (конструктор залов, две организации, покупка) по-прежнему
   требуют подготовленного стенда.
7. **PDF-QR проверяется только в отдельном CI-job'е.** Добавлен rasterizer
   (pymupdf + OpenCV) и печать через headless Chromium; локально тест
   пропускается без `TICKET_PDF_CHROME_BIN`. В прогоне установки билет
   создаётся тестовым платёжным режимом, а не боевым.
8. **AUD-024/025:** 4130-строчный редактор залов не декомпозирован, бенчмарки
   Konva 500..20000 мест не сняты. Серверные лимиты и spatial buckets есть,
   но заявлений об ускорении нет.
 9. **Не все операции с контентом доступны агенту.** Пять подготовок
    (`prepare_create_page`, `prepare_update_page`, `prepare_update_theme`,
    `prepare_update_seo`, `prepare_update_event`) реализованы; публикация
    страниц, загрузка медиа и удаление остаются в админке. Всего 43 инструмента:
    9 базовых + 16 диагностических + 13 контентных + 5 подготовок. Write-часть
    двухфазная, человек одобряет действие в админке.
10. **Хендшейк проверен по протоколу, но не через сторонний MCP SDK.**
    Feature-тесты выполняют реальные HTTP JSON-RPC `initialize → tools/list →
    tools/call` с Bearer-токеном. Установить `@modelcontextprotocol/sdk` для
    проверки совместимости с внешним клиентом (Codex/ChatGPT) в этой среде не
    удалось (npm-зависимость недоступна), поэтому совместимость с конкретным
    клиентом остаётся неподтверждённой. Панель админки показывает адрес и
    состав инструментов, но не выполняет `initialize`.
11. **Сегментация/аналитика/A-B/heatmap частично отключены** (`abtesting`,
    `heatmaps`, `ai` в реестре модулей disabled): это осознанное решение, не
    потеря функция; включение — отдельное решение с проверкой согласий.
12. **Живые платежи, SMTP, webhooks, Yandex Disk, отзыв устройств Checker и
    печать на киоске** требуют внешних аккаунтов и оборудования.
13. **Локальный сборщик использует системный `composer` из PATH**; в CI он
    ставится setup-php. Без composer сборка невозможна (это ожидаемо:
    зависимости должны ставиться по lock).
14. **Ограничение частоты MCP** — 60 запросов/мин на токен; скоуп по
    организациям работает, но редактирование полномочий идёт перевыпуском
    токена, а не на месте.
15. **Обновление до 1.16.3 на хостинге не проверялось.** Локально проверен
    переход с неизменного оригинального архива 1.16.1 на 1.16.2 без ручной
    подмены файлов (см. п. 4). Прогон обновления 1.16.2 → 1.16.3 на реальной
    установке Timeweb не выполнялся — это отдельный шаг приёмки.
