# ИИ-агент NABILET (MCP-сервер)

Внешний ИИ-агент (Claude Desktop, OpenCode, n8n и др.) подключается к системе
по протоколу MCP (Model Context Protocol) и отвечает на вопросы о продажах,
событиях и заказах. Сервер встроен в NABILET (модуль `Agent`) и работает на
обычном web-маршруте — без долгоживущих процессов, то есть на shared hosting.

## Границы полномочий (v1 — только чтение)

| Слой | Правило |
|---|---|
| Транспорт | `POST /mcp` (MCP Streamable HTTP), 60 вызовов/мин на токен |
| Аутентификация | Bearer-токен Sanctum (personal access token) |
| Роль | Токен только у staff-пользователя (`admin`/`manager`) |
| Способность | Ability `agent:read` — токен без неё получает 403 на любом вызове |
| Данные | Только организации, где состоит владелец токена; чужие данные неотличимы от несуществующих |
| Инструменты | Все объявлены `#[IsReadOnly]` + `#[IsIdempotent]` — агент ничего не меняет |

Действия (отмена заказа, возврат, создание события) — вне полномочий агента.
Это сознательная граница: доверие агента зарабатывается постепенно, запись
появится отдельным решением с явными аннотациями и подтверждением человека.

## Выпуск токена

Токен выпускается из консоли сервера:

```bash
php artisan nabilet:agent-token director@venue.ru
php artisan nabilet:agent-token director@venue.ru --name="Дежурный агент"
php artisan nabilet:agent-token director@venue.ru --list        # активные
php artisan nabilet:agent-token director@venue.ru --revoke-all  # отозвать прежние
```

- E-mail должен принадлежать пользователю с ролью `admin` или `manager`.
- Открытый текст токена показывается **один раз**; утерянный токен
  перевыпускается (`--revoke-all` + новая выдача), а не восстанавливается.
- Токен наследует роли владельца: данные ограничены его организациями.

## Инструменты

| Инструмент | Назначение | Основные аргументы |
|---|---|---|
| `sales_summary` | Сводные продажи за N дней: выручка (оплаченные заказы), заказы по статусам, проданные билеты | `days` (1–365, по умолч. 30) |
| `search_events` | Поиск событий по названию/статусу → `public_id` | `query`, `status`, `limit` (≤100) |
| `get_event` | Детали события: описание, сеансы, вместимость/остатки | `public_id` |
| `search_orders` | Заказы за N дней: фильтры статус/событие → `public_id` | `status`, `event_public_id`, `days`, `limit` |
| `get_order` | Детали заказа: позиции, билеты, контакты покупателя | `public_id` |

Правила экономии контекста (соблюдены в ответах):
- списки — только поля выбора (`public_id`, название, статус, суммы);
- полное описание события и ПДн покупателя — только в `get_*` по одному
  объекту;
- QR-пейлоад и хэши билетов агенту не выдаются никогда: это сам доступ
  к билету, а не информация о нём;
- идентификаторы во всех ответах — `public_id` (26 символов).

## Подключение клиентов

### OpenCode (`opencode.json`)

```json
{
  "mcp": {
    "nabilet": {
      "type": "remote",
      "url": "https://ваш-домен/mcp",
      "headers": {
        "Authorization": "Bearer {env:NABILET_AGENT_TOKEN}"
      },
      "enabled": true
    }
  }
}
```

Токен держите в переменной окружения (`NABILET_AGENT_TOKEN`), не в файле
конфигурации. Инструменты будут доступны как `nabilet_sales_summary`,
`nabilet_search_events` и т.д.

### Claude Desktop / другие клиенты

Любой MCP-клиент с remote-сервером и заголовком
`Authorization: Bearer <токен>`. OAuth не используется — только API-токен.

## Безопасность

- Токен = ключ к данным организации: хранить в менеджере секретов, не в
  репозитории и не в переписке.
- При утечке: `nabilet:agent-token <email> --revoke-all` — все agent-токены
  пользователя отозваны немедленно.
- Полная очистка токенов отзывает доступ мгновенно, но не «хвост» уже
  утёкших данных — держите в уме, что агент мог успеть скопировать данные
  в свой контекст.
- Логи: запросы к `/mcp` видны в стандартных логах сервера вместе с
  `X-Request-Id` — инцидент разбирается по журналу, как и обычные запросы.

## Ограничения текущей версии

- Только чтение (см. выше).
- `sales_summary` не включает посетителей сайта: таблица аналитики
  глобальная, честно срезать её по организации нельзя.
- Инвентарь сеанса без `inventory_items` отдаётся как `inventory: null`
  («не настроено»), а не нули.
