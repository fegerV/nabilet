# Changelog

Все значимые изменения NABILET Core оформляются в этом файле.

Формат — [Keep a Changelog](https://keepachangelog.com/ru-RU/1.1.0/), версионирование — [SemVer](https://semver.org/).

## [Unreleased]

### Fixed

- Установочный архив теперь включает `scripts/updater-recover.php`: без него
  Updater не мог скопировать аварийный скрипт в `storage/` и падал на старте
  обновления до миграций. Обнаружено сквозным прогоном 1.16.0 → 1.16.1.
- `ReleaseExtractor` принимает реальный архив: записи `storage/**` пропускаются,
  служебные `.gitignore` и метаданные `vendor/**` разрешены, `scripts/**` входит
  в whitelist. Раньше распаковка падала на первом же `.gitignore` из vendor.
- `recoverInterrupted()` больше не считает прерыванием нормальную границу тиков:
  `locked_at` снимается между состояниями по дизайну, признак прерывания —
  давность `updated_at`. Раньше обновление неизменно переходило в
  `failed_after_swap` на тике после подмены файлов.

### Added

- `tools/verify-release-signature.php`: локальная проверка подписи манифеста и
  SHA-256 архива без Laravel. Полный контур «генерация ключей → подпись при
  сборке → проверка верификатором» проверен сквозно.
- Экспорт обезличенной диагностики `GET /api/v1/admin/system/diagnostics/export`:
  файл JSON без паролей, токенов и персональных данных, с `Cache-Control: no-store`.
  Отчёт собирается тем же сервисом, что и MCP `get_installation_report`.
- Пять двухфазных инструментов подготовки контента (`prepare_create_page`,
  `prepare_update_page`, `prepare_update_theme`, `prepare_update_seo`,
  `prepare_update_event`) под полномочие `agent:content:write`. Как и остальные
  write-инструменты, они только сохраняют неизменяемый снимок; исполнение —
  после одобрения человеком через `confirm_agent_action`. Страницы создаются
  черновиками, тема объединяется с существующими настройками, SEO — в
  organization scope.
- Браузерный Playwright-сценарий `install-smoke.spec.ts` на только что
  установленный стенд и его запуск в job'е `smoke` релизного workflow
  (вместе со снимками/трассировками при падении). Локальный прогон в этой среде
  блокируется песочницей браузера (`ERR_NETWORK_ACCESS_DENIED` на loopback).
- 13 read-only контентных инструментов MCP: `search_pages`, `get_page`,
  `search_media`, `get_site_settings`, `get_theme_settings`, `get_seo_report`,
  `search_venues`, `search_halls`, `get_hall_schema`, `validate_hall_schema`,
  `validate_event`, `validate_ticket_template`, `validate_payment_configuration`.
  Все данные ограничены организациями владельца токена; настройки маскируют
  ключи с password/token/secret; валидация схемы вызывает правила редактора,
  а шаблона билета — домен `TicketTemplateConfig`.
- Панель «Подключение MCP» в админке (`GET /api/v1/admin/agent/connection`):
  адрес и транспорт сервера, готовый конфиг клиента, реальный перечень
  инструментов из реестра `NabiletAgentServer` и проверка готовности (маршрут
  `/mcp` + активный токен с `agent:read`).

### Tests

- `AgentDiagnosticsToolsTest`: 8 тестов / 92 утверждения, включая endpoint
  подключения; `AgentContentToolsTest`: 5 тестов / 72 утверждения (скоуп,
  маскирование, валидаторы); `AgentContentWriteFlowTest`: 4 теста / 37
  утверждений (prepare → approve → confirm, идемпотентность, scope);
  `DiagnosticsExportTest`: 2 теста / 9 утверждений; ManifestVerifierTest: 4 теста / 25 утверждений; полный PHPUnit — 1532
  теста / 6842 утверждений.

## [1.16.1] - 2026-11-27

Тема релиза — стабилизация и воспроизводимый выпуск архива.

### Added

- Портативный сборщик установочного архива `scripts/build-hosting-zip.php`
  и workflow `.github/workflows/release-hosting.yml`: сборка из чистого
  checkout, `npm ci`/typecheck/тесты/production build, production `composer
  install` строго по `composer.lock`, явный список файлов (секреты, логи,
  бэкапы, пользовательские медиа и dev-пакеты физически не попадают в
  staging), проверка ZIP и распаковка с чистой установкой на отдельной БД.
  Манифест содержит `version`, `commit_sha`, `released_at`, SHA-256 и
  подпись при наличии ключа. `scripts/build-hosting-zip.ps1` стал тонкой
  обёрткой над тем же сборщиком — больше нет robocopy и второй реализации.
- Гейт согласования версий `tools/verify-release-version.php` (config,
  package.json, CHANGELOG). В CI проверяется на каждом коммите, в релизном
  workflow — строго, с датированным разделом CHANGELOG.
- 16 read-only диагностических инструментов MCP (`get_system_status`,
  `get_system_requirements`, `get_cron_status`, `get_queue_status`,
  `get_recent_errors`, `get_failed_jobs`, `get_database_status`,
  `get_module_status`, `get_integration_status`, `get_backup_status`,
  `get_update_status`, `get_application_version`, `get_api_capabilities`,
  `get_installation_report`, `run_readonly_selfcheck`, `get_route_status`)
  на базе одного обезличенного `AgentDiagnostics`. Секреты, payload задач,
  стектейсы и персональные данные в ответ не попадают.

- One-click обновление системы (`/admin/updates`, `docs/ONE_CLICK_UPDATE.md`):
  подписанный манифест релиза, загрузка ZIP вручную как fallback, подготовка в
  staging, замена каталогов с откатом, миграции и проверка отдельными тиками
  `nabilet:update:tick` по крону. `.env`, `storage/`, пользовательские файлы
  `public_html/` не перезаписываются; перед обновлением требуется полный бэкап.
  Аварийный откат без Laravel — `scripts/updater-recover.php`. Если Яндекс.Диск
  не подключён, перед обновлением создаётся локальный полный бэкап вместо
  блокировки (`NABILET_UPDATE_ALLOW_LOCAL_BACKUP`).

### Fixed

- CI: frontend-задача падала на `npm ci` до запуска проверок — раннер поднимал
  Node 22, а зависимости в lock требуют `^22.22.2 || ^24.15.0 || >=26`. Раннер
  переведён на Node 24, версия в `package-lock.json` синхронизирована с
  `package.json`.
- Слиты исправления из веток `fix/ticket-builder-audit`,
  `fix/yandex-hallplan-import` и `fix/updater-reliability`: дизайн билета и
  байты изображения замораживаются при выпуске (QR проверяется внешним
  декодером), импорт Афиши сохраняет нестандартные номера мест и требует
  подтверждения организатором, обновления ведут журнал, блокировки и явно
  различают состояния миграций. SQL-бандлы снова согласованы (88 таблиц /
  955 колонок, `EXPECT_COLUMNS=955`).
- Модель `IdempotencyKey` приведена к реальной схеме: вместо выдуманных
  `key`/`value` — `scope`/`key_hash`/`request_hash`/`response_*`/`locked_at`,
  автоинкрементный `id` и отсутствующий `updated_at` описаны явно. Исключение
  из `verify-models-schema.php` удалено (храповик только сужается).
- `EnsureIdempotency`: запрос, проигравший гонку между `find()` и `lock()`, больше
  не исполняет хендлер после проглоченного duplicate INSERT. `lock()` теперь
  возвращает факт захвата; проигравший перечитывает строку и получает
  `IN_FLIGHT`/`REPLAY`/`CONFLICT` вместо второго побочного эффекта.

### Tests

- `AgentDiagnosticsToolsTest`: регистрация и `#[IsReadOnly]` всех 16 новых
  инструментов, обезличенность отчёта, отсутствие payload и exception в
  `get_failed_jobs`, присутствие критических маршрутов. Полный PHPUnit — 1485
  тестов / 6521 утверждений.
- чистый smoke-прогон распакованного архива на отдельной БД — 45/45 проверок
  (мастер, отказ установщика после завершения, health 1.16.1, витрина).
- `ConcurrentBookingTest`: детерминированная гонка двух покупателей за последнее
  место. Второй резерв внедряется на чтении сеанса внутри транзакции первого и
  получает 409 `SEAT_UNAVAILABLE` — ровно один активный холд, доступность не
  уходит в минус. Дополнительно проверена ёмкость standing-зоны (2+1 → 409) и
  форма резерва `UPDATE ... WHERE available_quantity >= ?`.
- `IdempotencyRaceTest`: гонка middleware на тестовом роуте — проигравший между
  `find()` и `lock()` выполняет хендлер один раз и получает replay, запрос после
  lock — 409 `REQUEST_ALREADY_PROCESSED`, повтор после завершения — replay с
  заголовком `Idempotent-Replay`, другое тело с тем же ключом — 409
  `IDEMPOTENCY_KEY_REUSED`. Тест падает на старом коде и зелёный после фикса.
- Убраны дублирующие ключи `venue_id` в 24 массивах тестовых фикстур — невидимая
  мусорная запись после массового переименования `hall_id`; PHPStan level 5
  перестал ругаться на эти места.
- `PromoConcurrencyTest`: гонка D-6 — конкурент успевает исчерпать
  `max_redemptions` между перепроверкой `per_user_limit` и условным UPDATE;
  второй redeem обязан получить `PROMO_CODE_EXHAUSTED`. Плюс последовательный
  сценарий одноразового кода. Тест падает, если убрать условие
  `redemptions_count < max_redemptions` из UPDATE.

## [1.16.0] - 2026-11-25

Тема релиза — редактор схем залов.

### Fixed

- `Space`+тяга снова включает панораму, как обещает подсказка в футере; Space не
  создаёт зоны/секторы и не переключает инструмент, отпускание и потеря фокуса
  снимают режим.
- Программная правка модели во время публикации больше не планирует автосохранение:
  схема неизменяема на весь запрос, а не только на уровне disabled-кнопок.
- Публичный `GET /venues/{publicId}/schema-versions` больше не падает 500
  `TenantContextMissingError` для гостя: площадка и версии читаются в bypass.
- Фон зала проверяется по размеру до чтения файла: data URL свыше 1.5 МБ
  отвергается с понятным сообщением, а не ломает автосохранение на сервере.
  Лимит `nabilet.hall_schema.max_payload_bytes` теперь описан в конфиге и `.env`.
- Горячие клавиши редактора не перехватывают ввод, когда фокус на кнопке.
- Щипок двумя пальцами масштабирует схему вокруг середины пальцев — на
  планшете больше не нужно колесо мыши; эмулированный mousedown во время
  щипка не создаёт зоны и не начинает перетаскивание.
- Выбор опубликованной схемы для сеанса/события идёт по `version`, а не по
  автоинкрементному `id`, и использует константы `SchemaVersionState` вместо
  литералов statuses.

### Tests

- `useEditorHistory`: снимок до мутации, один снимок на жест, лимит 50, `reset()`
  при смене серверной версии; Space-панорама; гостевой список версий площадки.
- `CheckoutFlowTest`: один HTTP-прогон «площадка → схема → событие → сеанс →
  инвентарь → корзина → заказ → платёж → подписанный вебхук → билет с QR →
  `my-tickets` → check-in validate/use ». Раньше цепочка была покрыта по звеньям,
  но стыки (provider_payment_id, QR из вебхука, сканирование выданного билета)
  не проверялись ни одним тестом.

### Changed — конструктор схем

- Список версий площадки больше не тащит `schema_json` (до 2 МБ на версию):
  отдает лёгкие строки, а редактор догружает геометрию выбранной версии через
  новый `GET /venues/{publicId}/schema-versions/{versionId}`. Черновик по этому
  пути виден только сотрудникам.
- Один палец на планшете повторяет мышиные жесты редактора: рамка выделения,
  стоячая зона, сектор и перенос мест. Два пальца по-прежнему масштабируют.
  Эмулированное браузером `mousedown` после касания игнорируется, поэтому жест
  не создаёт объект дважды.

### Fixed — шаблоны писем

- Список переменных редактора теперь собирается из всех семейств писем, включая
  розыгрыш (`raffle_title`, `prize_place`, `prize_title`); демо-данные покрывают
  `action_url`, срок, `sales_note` и призы — превью больше не показывает
  незаменённые `{{...}}`.
- Сид сверяет и семейство `account.*`, а не только заказы/подписки/розыгрыши.
- В админке добавлены названия и группы «Подписки»/«Розыгрыши» для всех 13 писем;
  предпросмотр показывает текстовую версию.
- Добавлены HTTP-тесты редактора (список переменных, неизменяемость кода,
  приоритет несохранённого черновика, запрет `tickets_html` из запроса).

### Fixed — встраивание

- Сниппет проверяет `e.origin` и находит рамку по `e.source` среди всех
  `iframe[data-nabilet-embed]` — поддельное сообщение и конфликт двух виджетов
  на странице партнёра больше не ломают мост.
- Страница `/admin/embed`: выбор события из списка и переход «открыть витрину»,
  надёжное копирование с fallback для HTTP, блокировки на время запросов,
  раздельная загрузка ключей/доменов/организаций/событий.
- Убраны устаревшие утверждения «оплата ещё не на embed-API» в коде и документах.

## [1.15.0] - 2026-11-21

Тема релиза — исправление конструктора билетов и вертикального формата.

### Fixed — WYSIWYG

- Билет покупателя больше не расходится с конструктором: применяются поворот
  и прозрачность элементов, изображения из медиатеки рисуются настоящей
  картинкой, штрихкод — локально сгенерированным CODE128 вместо «|| || ||».
- QR больше не может проявить устаревшую картинку при быстрой смене payload.
- Градиент с единственным цветом `from` больше не превращается в сплошной фон.

### Changed — формат

- `format` шаблона выводится из размеров холста: вертикальный → `mobile`,
  горизонтальный → `desktop`. Раньше всегда писался `mobile`, даже для 800×400.
- Заготовки конструктора (600×400) масштабируются под текущий холст, поэтому
  применяются и к вертикальному билету 400×600, не переворачивая его.
- Добавлены переключатели «Вертикальный / Горизонтальный» и пересчёт элементов
  при смене размера. Старые записи без размеров открываются вертикальными.

### Added — удобство

- Переключатель «активен / выключен» в списке шаблонов.
- Валидация названия и лимитов до запроса, ошибки внутри модалки вместо `alert`.
- Подтверждения удаления/очистки внутри редактора вместо `window.confirm`.
- Кнопка «Повторить» при ошибке загрузки шаблона.
- В карточке события — переход к выбранному макету рядом с «создать макет
  для этого мероприятия» (уникальный дизайн на концерт).

### Tests

- Компонентные тесты рендера билета и тесты масштабирования/формата.

## [1.14.0] - 2026-11-21

Тема релиза — возврат бонусов при частичном возврате денег.

### Changed

- `partially_refunded` больше не исключён из компенсации: возвращается
  пропорциональная доля списанных бонусов по накопленной сумме возврата.
  Итог нескольких частичных возвратов сходится к полному, но никогда не
  превышает списанное. Последующий полный возврат добирает только остаток.
- Идемпотентность строк возврата: `partial_refund:{order_id}:{refunded_minor}` для
  частичных и прежний `refund:{order_id}` для полного. Повтор джобы не удваивает
  начисление.
- Правило округления вынесено в `BonusRefundPolicy` (чистый класс, юнит-тесты на
  границах). Сумма возврата берётся из строк `refunds`, а не из нового поля заказа.

## [1.13.0] - 2026-11-21

Тема релиза — денежный флоу виджета на `/api/v1/embed/*`.

### Changed

- Карта зала, холды, чекаут и платёж внутри встраиваемого виджета теперь идут
  через embed API. Обычная витрина продолжает пользоваться публичными ручками —
  переключение включается только при `embed_token` в адресе рамки.
- Embed `GET /sessions/{id}/seatmap` отдаёт конверт, совместимый с витринным
  `/inventory` (поля мест, `meta.max_tickets_per_order`, `meta.stage_side`),
  плюс прежние поля `inventory`/`session`/`schema`.
- Embed-холд принимает ULID из seatmap наравне с числовым id.
- Embed-чекаут принимает `bonus_amount` и `referral_code`, как витринный.
- `stageSide()` вынесен в `Inventory\Support\StageSide`: витрина и embed считают
  сторону сцены по одному правилу.

### Fixed

- Запросы из iframe приходят с Origin нашего домена — embed API теперь разрешает
  same-origin при валидном токене; чужие Origin по-прежнему отклоняются.
- `CartItemResource` внутри embed больше не падает 500 из-за незагруженных
  связей `inventoryItem.seat.row.sector`.

### Tests

- Happy-path embed API (seatmap → cart → item → order → payment) и транспорт
  виджета. В браузере на партнёрском сайте проведён полный сценарий: все пять
  embed-запросов 201/200, постсообщения `order`/`payment` доходят родителю.

## [1.12.1] - 2026-11-21

### Fixed

- `frame-ancestors` учитывает нестандартный порт сайта партнёра (стенд на
  `partner.example:8443`): точный origin из `Referer` добавляется в CSP только

## [1.12.0] - 2026-11-21

Тема релиза — запасные каналы продаж для виджета на чужом сайте.

### Added

- Fallback-окно виджета схемы зала при **любой** ошибке загрузки: нет сети, 5xx,
  неизвестный сеанс или схема. Вместо пустой рамки покупатель видит понятное сообщение,
  кнопку «Повторить», телефон, Telegram, WhatsApp, e-mail и ссылку «Все контакты».
- Контакты для fallback настраиваются в «Витрина → Контакты». Телефон и e-mail
  по умолчанию берутся из карточки организации; мессенджеры и текст задаёт
  администратор. Все значения проходят белый список нормализации (никакого HTML
  и `javascript:` в `href`).

### Fixed

- Виджет теперь действительно открывается на сайте партнёра: `ApplySecurityHeaders`
  учитывает `?embed_token=` и снимает `X-Frame-Options`, а `frame-ancestors`
  строится из whitelist доменов embed-ключа. Раньше хук `embed.allowed_ancestors`
  никто не регистрировал, и рамка блокировалась браузером ещё до загрузки схемы.
- Реестр хуков (`HookRegistry`) зарегистрирован синглтоном: `add_filter()` и
  `apply_filters()` работали с разными объектами, поэтому хук молча не действовал.

  version-aware: `DROP CONSTRAINT` на MySQL ≥ 8.0.19 / MariaDB ≥ 10.2.1,
  `DROP CHECK` на MySQL 8.0.16–8.0.18, а движки, которые CHECK вообще не
  исполняют (MySQL < 8.0.16, MariaDB < 10.2.1), отсекаются гардом целиком —
  ставить неисполняемые «инварианты» по деньгам так же бессмысленно, как
  молча их игнорировать. Логика определения версии сервера работает и на
  MariaDB с префиксом совместимости (`5.5.5-10.x.y-MariaDB`).
- **Подсказка поля «Хост БД» в мастере установки** нейтральна: placeholder
  `localhost`, без упоминания хостинга.

## [1.0.2] - 2026-11-13

Третья сборка архива установки `nabilet-hosting-v1.0.2-20261113.zip`.
**Структура архива перевёрнута в WordPress-style** (фидбек с хостинга):
внутри архива больше нет папки-обёртки `nabilet/` — корень архива равен
docroot, архив распаковывается прямо в `public_html`, и там же лежат
`index.php`, `.htaccess`, `.user.ini`, `robots.txt`, `favicon.svg` и
системные каталоги (`app/`, `config/`, `vendor/`, `storage/`, …). Файловый
менеджер хостинга умеет распаковывать только внутрь `public_html`, и
переносить содержимое папки-обёртки на уровень выше руками не нужно.

### Changed

- `.htaccess` docroot дополнен: системные каталоги (`app`, `bootstrap`,
  `config`, `database`, `lang`, `public`, `resources`, `routes`, `dist`,
  `vendor`) закрыты от прямого HTTP-доступа (403), блок dotfiles сохранён,
  Authorization-заголовок пробрасывается как раньше.
- **Медиа отдаются без симлинка**: `/storage/{path}` отображается в
  `storage/app/public/{path}` правилом `.htaccess` с условием `-f` (нет
  зацикливания, несуществующие файлы уходят во фронт-контроллер). Раньше
  `/storage/...` на хостинге отвечал 404: симлинк `public/storage`, который
  создаёт `storage:link`, находится вне DocumentRoot. Условие распространяется
  только на существующие файлы — приватное хранилище (`storage/app/private`,
  логи, кэш) остаётся недоступным по HTTP.
- `robots.txt`, `favicon.svg` и og-картинки из `public/` кладутся в корень
  архива: `/robots.txt` теперь отдаётся на хостинге физически (раньше файл
  был только в `public/`, при DocumentRoot=`public_html` отвечал 404).
- Сборка архива автоматизирована скриптом `scripts/build-hosting-zip.ps1`
  (состав, чистка runtime-мусора и верификация ZIP-записей — в скрипте).
